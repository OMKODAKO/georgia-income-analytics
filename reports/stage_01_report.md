## 3. Data Collection Script — `src/data_collection.py`
| მოთხოვნა | რეალიზაცია |
|---|---|
| ოფიციალური URL-ები | რეესტრი `SOURCES` (34 წყარო, ყველა `geostat.ge/media/`) |
| HTTP პასუხი | სტატუსი 200; HTML შეცდომის გვერდი უარყოფილია |
| რეალური ფორმატი | შიგთავსით (magic bytes + ZIP სტრუქტურა), არა გაფართოებით |
| ზომა | მიღებული ბაიტები = `Content-Length` (gzip-ით მიწოდებულ HTML-ზეც სწორად) |
| ზედმეტი ჩამოტვირთვა | თუ ფაილი არსებობს და SHA-256 ემთხვევა → `skipped_present` |
| Raw-ის დაცვა | არსებულ, განსხვავებულ ფაილს **არასდროს გადააწერს** — ჩერდება შეცდომით |
| ლოგი | `data/raw/download_log.csv` — დრო, ქმედება, HTTP, ზომა, ფორმატი, SHA-256, URL, შეტყობინება |
| URL და თარიღი | `data/raw/manifest.json` |
| ბმულების შემოწმება | `python src/data_collection.py --check-links` |

რეალურად დაფიქსირებული პრობლემები, რომლებიც სკრიპტმა დაიჭირა: Geostat-ის სერვერი წყვეტს კავშირს ხშირი
მოთხოვნებისას (→ პაუზა 8 წმ + exponential back-off); HTML გვერდები gzip-ით მოდის (→ ზომა იზომება გადაცემულ ბაიტებზე).

## 9. რა გამოგვადგება Stage 02-ში
1. **მთავარი:** LFS `ecstat` (+ `id`, `personal_weights`, `familysize` 2017–19; `demographic` 2020+) — დაქირავებულები,
   `Sex`, `Age`, `Region`, `Urban_Rural`, `Education`, `Occupation`, `Branch/Brunch`, `Status`, hours, informality,
   earnings band, `P_Weights`, `UID`/`DiaryID`.
2. **დამხმარე (ცალკე):** HIES `tblincomes` + `sysschedule` + `familysize` + `tblshinda02` — ოჯახის შემოსავალი
   ოჯახის შემადგენლობის/უფროსის სქესის მიხედვით.
3. **ვალიდაცია/დეფლაცია:** `wages_gpg` (ოფიციალური adjusted GPG 2020–2025), `wages_median`, `cpi_2010`.

**Stage 02-ისთვის გადასაწყვეტი:** 2017 earnings კოდი „10" (62 ჩანაწერი); LFS 2018 2 რიგი `UID`-ის გარეშე;
2023+ refusal = system-missing; ორი მეთოდოლოგიური პერიოდის (2017–19 / 2020–25) ცალ-ცალკე თუ ერთად ანალიზი.
