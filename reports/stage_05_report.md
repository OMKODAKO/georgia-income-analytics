## 1. Stage 04-ის აუდიტი
- Stage 04-ის ყველა ტესტი გავიდა; მონაცემები, წონები, სქესის კოდირება (female/male), წლები და პერიოდი დადასტურდა.
- **ინდივიდუალური შემოსავალი არსებობს** (LFS) — საოჯახო შემოსავალი არ გამოყენებულა.
- **Target:** *დაქირავებულის ხელზე ასაღები თვიური ხელფასის შეფასება, რეალური 2025 GEL* — ინტერვალის შუა წერტილი
  (ღია ზედა ინტერვალში Pareto). 2020–25-ში მხოლოდ **72 განსხვავებული მნიშვნელობაა** (12 ინტერვალი × 6 წელი) →
  ინტერვალის შიგნით ცვალებადობა უცნობია, რაც მიღწევადი სიზუსტის ზედა ზღვარს ქმნის.
- **ერთი ადამიანი რამდენჯერმეა მონაცემებში:** 2020–25-ში ოჯახი 3 წლამდე ჩანს (15.8 ათასი განმეორება) →
  დაყოფა ოჯახების მიხედვით. 2017–19-ში ოჯახი წლებს შორის ვერ უკავშირდება (შეზღუდვა).
- **Leakage-ის რისკი:** ინტერვალის კოდები, საზღვრები, საათობრივი ხელფასი და ნებისმიერი შემოსავლიდან მიღებული ცვლადი
  ამოღებულია (`LEAKAGE_COLUMNS`, ტესტით შემოწმებული).
- ძირითადი ანალიზი — **2020–2025** (81,166 ჩანაწერი, მიმდინარე მეთოდოლოგია); 2017–2019 — რეპლიკაცია.

## 3. Preprocessing და დაყოფა
- `Pipeline` + `ColumnTransformer`: რიცხვითი — median imputation (+ missing indicator) + `StandardScaler`;
  კატეგორიული — „missing" კატეგორია + `OneHotEncoder(handle_unknown="ignore")`. **ყველაფერი ისწავლება მხოლოდ
  training მონაცემზე** (ტესტი: scaler-მა მხოლოდ 56,999 training რიგი ნახა).
- **დაყოფა ოჯახების მიხედვით** (`GroupShuffleSplit`, random_state=42): train 56,999 (70.2%) / validation 12,159 (15.0%) /
  test 12,008 (14.8%); **0 ოჯახი ორ ნაწილში**.
- Outliers: Stage 02-ში გამოკვლეული (ნამდვილი მნიშვნელობები); log target ამცირებს მაღალი მნიშვნელობების გავლენას.

## 4. ალგორითმები და Hyperparameter Optimization
| მოდელი | ძებნა (მხოლოდ train, 3-fold GroupKFold ოჯახებით, MAE) | დრო |
|---|---|---|
| Linear Regression | — (საბაზისო) | <1 წმ |
| Ridge | Grid: α ∈ {0.01 … 1000} | 3 წმ |
| Random Forest | Random, 6 კომბინაცია: depth, min_samples_leaf, max_features (150 ხე) | 17 წმ |
| Gradient Boosting | Random, 10: learning rate, iterations, leaves, min leaf, L2 (`HistGradientBoostingRegressor`*) | 195 წმ |
| XGBoost | Random, 10: learning rate, n_estimators, depth, min_child_weight, subsample, colsample, λ | 40 წმ |

\* sklearn-ის კლასიკური `GradientBoostingRegressor` ერთნაკადიანია და ~57K × 80 სვეტზე CV-ძებნით პრაქტიკულად
ზედმეტად ნელი — გამოყენებულია sklearn-ის ჰისტოგრამული gradient boosting (იგივე ალგორითმული ოჯახი).
**Test set ძებნაში არ გამოყენებულა**; მოდელი არჩეულია validation-ზე; test — ერთხელ, ბოლოს.

XGBoost-ის საუკეთესო პარამეტრები: learning_rate 0.034, n_estimators 654, max_depth 6, min_child_weight 15,
subsample 0.93, colsample_bytree 0.51, reg_lambda 2.53.

  მოდელს ზღუდავს ცვლადების ინფორმაცია და ინტერვალური target.
- **დროითი ვალიდაცია** (train 2020–23 → test 2024–25, ოჯახები არ მეორდება): XGBoost MAE 293.9, R² 0.414,
  საშუალო შეცდომა **−140 GEL** — 2024–25-ის რეალური ზრდა მოდელმა ვერ „იწინასწარმეტყველა" (ხეები წლის მიღმა ვერ
  ექსტრაპოლირებენ). → **მოდელი ახალ წლებზე ხელახლა უნდა გაიწვრთნას.** წრფივი: MAE 328.0, შეცდომა −77.
- **რეპლიკაცია 2017–2019** (იგივე პროტოკოლი): XGBoost MAE 261.9, R² 0.444; წრფივი 298.0 / 0.325 — იგივე სურათი.

## 11. შეზღუდვები
1. **ინტერვალური target** — 72 მნიშვნელობა; R² ≈ 0.45 მნიშვნელოვნად შეზღუდულია გაზომვით (log-ზე 0.55).
2. **დროითი გადატანა სუსტია** (2024–25-ზე −140 GEL) — მოდელი ყოველწლიურად უნდა განახლდეს; წლის მიღმა ექსტრაპოლაცია არასანდოა.
3. მხოლოდ **დაქირავებულები**; non-response (23% 2025-ში) არ არის კორექტირებული.
4. **სამუშაო სტაჟი, საწარმო, თანამდებობა არ არის** — მოდელი ამ ინფორმაციას ვერ იყენებს.
5. მოდელი **შეუწონავადაა** გაწვრთნილი (პროგნოზირების ამოცანა); შეწონილი MAE ცალკეა მოცემული (291 GEL test-ზე).
6. 2017–19-ში ოჯახის იდენტიფიკატორი მხოლოდ კვარტლის შიგნითაა → იქ დაყოფა ნაკლებად იცავს leakage-ისგან.
7. Gradient Boosting — ჰისტოგრამული ვერსია (`HistGradientBoostingRegressor`), არა კლასიკური.
8. **Feature importance / SHAP / gender flip — მოდელის თვისებებია, არა მიზეზშედეგობრივი ეფექტი.**
9. **ეს მოდელი არ უნდა გამოიყენებოდეს ინდივიდებზე გადაწყვეტილებების მისაღებად** (ხელფასის დადგენა, დაქირავება).

## 12. პასუხები
1. **რამდენად კარგად ვწინასწარმეტყველებთ?** — ზომიერად: საუკეთესო მოდელი ხსნის ხელფასის ვარიაციის ~45%-ს (log-ზე 55%),
   საშუალო შეცდომა ~272 GEL (~33% საშუალო ხელფასისა), მედიანური შეცდომა ~186 GEL. ზღვარს ქმნის ინტერვალური
   გაზომვა და ცვლადების სიმცირე, არა მონაცემების რაოდენობა.
2. **ყველაზე მნიშვნელოვანი ფაქტორები:** დარგი და პროფესია, შემდეგ წელი (რეალური ზრდა), სამუშაო საათები, სქესი,
   განათლება და რეგიონი. ასაკს თავისთავად მცირე წვლილი აქვს.
3. **Gender-ის დამატებისას:** სიზუსტე ოდნავ, მაგრამ ყველა მოდელში მდგრადად უმჯობესდება (MAE −5 GEL); ქრება
   სისტემატური მიკერძოება (ქალებზე გადაჭარბება, კაცებზე შემცირება); მოდელი ნაგულისხმევად ~16%-იან სხვაობას
   „სწავლობს" ტოლი მახასიათებლებისას. Gender-ის გარეშეც სქესის ინფორმაცია სხვა ცვლადებშია (AUC 0.89).
4. **შეცდომები ქალებისა და კაცებისთვის:** აბსოლუტურად ქალებისთვის ნაკლებია (MAE 230 vs 317), ფარდობითად ტოლია
   (~33%). მიკერძოება: A — ქალი ≈0, კაცი −27 GEL; B — ქალი +39, კაცი −67 (სხვაობა მნიშვნელოვანია, CI 83–128).
5. **შეგვიძლია თუ არა დასკვნა შემოსავლის სხვაობაზე?** — **მხოლოდ აღწერითი:** ML ადასტურებს Stage 04-ის შედეგს
   (ტოლი დაკვირვებადი მახასიათებლებისას ~16–17% სხვაობა) და აჩვენებს, რომ სქესი პროგნოზისთვის ინფორმაციულია.
   **ვერ** დავასკვნით, რომ სქესი ხელფასის სხვაობის **მიზეზია**, ან რომ სხვაობა დისკრიმინაციაა — მოდელი
